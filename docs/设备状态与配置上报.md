# 设备状态与配置上报（固件 ↔ 网关 ↔ App）

> **面向对象**：嵌入式 / 固件  
> **更新**：2026-09-21（`motion` 增加 `stand` 站；本篇为姿态/状态/配置的准绳）  
> **关联**：App 查询 `GET/POST /api/app/v1/device/status`（管理端 `/api/v1/device/status` 同源，多一个 token）  
> **不在本篇重复**：下行命令全表见 [三方对表](./三方对表-命令与上报.md)；WSS 握手与音频帧见 [嵌入式接口使用文档](./嵌入式接口使用文档.md)  
> **在线查阅**：测试台 **协议文档 → 设备状态与配置**（`/#docs-device-status`）

---

## 1. 设计原则（请先读）

| 数据类型 | 谁提供真值 | 固件要不要报 |
|----------|------------|--------------|
| **在线** `online` | **仅服务端**（WS 连接 + Redis TTL） | ❌ 不必报「我在线」；维持 25s Ping/`type=ping` 即可 |
| **运行态** `last_state` / `last_event` / `in_sleep` | 设备 `type=status`（推荐） | ✅ 状态变化时立刻发 |
| **功耗档位** `tier` | 设备 `ping`/`status` | ✅ 档位变化立刻发；见 §2.4 |
| **电量/信号等快照** `bat`/`charge`/`rssi`/`db`… | 设备 `ping`/`status`/音频附带 | ✅ 25s 心跳建议全带 |
| **配置** `volume`/`sensitivity`/`sleep_*`… | **设备上报优先**；App 改设置后网关记影子 | ✅ 建议周期或变更时带；见 §3 |

**配置双通道**：

1. **设备上行真值**（推荐）：`ping` / `status` 里带 `volume` 等 → 网关 `config_source=device`
2. **App 下行影子**（兜底）：App 调 `set_volume` 等命令后，网关先记「期望值」→ `config_source=shadow`，等设备上报后覆盖为 `device`

## 2. 固件上报：推荐字段（`type=ping` / `type=status`）

与 §2.1 双通道一致；**配置字段两通道都支持**，建议：

- **25s `type=ping`**：带 `bat`~`ts` + **配置字段**（包长约 +50 字节，可接受）
- **状态变化 `type=status`**：额外带 `event` / `state` / 定位；**录音开始/结束务必立刻发**

### 2.1 配置类上行字段（2026-08 新增）

| 字段 | 类型 | 取值 | 必带 | 说明 |
|------|------|------|------|------|
| `volume` | int | **0~100** | 建议 | 喇叭音量；与 `set_volume` 一致 |
| `sensitivity` | int | **0~100** | 建议 | 麦克风灵敏度；与 `set_sensitivity` 一致 |
| **`auto_record`** | **0/1** | 自动录音开关 | **建议（新固件）** | **1=开 / 0=关**；与 `enable_auto_record` 一致；网关据此过滤上行录音 |
| `translate_enabled` | **0/1** | 自动录音开关（旧名） | 兼容 | 与 `auto_record` 同义；仅报旧字段时网关也会同步 |
| `sleep_enabled` | **0/1** | 夜间休眠总开关 | 建议 | 与 `enable_sleep` 一致 |
| `sleep_window` | string | **`"0:6"`** | 建议 | 休眠时段：`开始小时:结束小时`（24h，与 `set_sleep_window` 一致） |
| `loc_interval_ms` | int | 毫秒，如 `30000` | 可选 | 定位上报间隔；与 `set_loc_interval` 一致 |

> 缺省某字段 = **不刷新**该项快照（不会把 App 已有值误清成 0）。

### 2.1.1 `auto_record` 上报与网关处理（定稿）

| 环节 | 约定 |
|------|------|
| **设备默认** | 自动录音关：`auto_record=0` |
| **App 状态默认** | 未 ACK / 未上报前，`/device/status` 的 `auto_record` 恒为 **`false`** |
| **下行** | `enable_auto_record`，`data`=`"true"` / `"false"`（亦兼容 `1`/`0`）；旧名 `enable_translate` 同语义 |
| **ACK** | 设备执行后回 `{"type":"ack","cmd":"enable_auto_record","result":0}`（成功）；**仅成功 ACK 后**网关才把状态写成下发值 |
| **设备上报** | `ping` / `status` 带 `"auto_record":0\|1`（推荐）；旧字段 `translate_enabled` 仍兼容，二者互相同步 |
| **真值优先级** | 设备上行 `auto_record` **覆盖** ACK 写入值 |
| **与音频分流** | `auto_record` 控制设备是否自动产生**录音文件**；网关按 `kind`（0 事件流 / 1 文件）分桶，默认两路都存、翻译只走事件流（见 `docs/upload_audio.txt`、`audio.*` 配置） |

**时序（开关状态）：**

```text
默认 auto_record=false
    → App 下发 enable_auto_record data=true
    → 设备 ACK result=0
    → 网关状态改为 true
    → 设备 ping/status 回显 "auto_record":1
```

**音频两路（与 auto_record 正交）：** 同一次叫声设备可能上事件流 + 录音文件两份；网关按 `kind`（缺省回退 `db`）分桶，**互不混拼**。默认 `accept=both`、`translate=event`、`archive_other=true`。

**上行示例（心跳 / 状态）：**

```json
{
  "type": "ping",
  "bat": 74,
  "auto_record": 1,
  "ts": 1787808964108302
}
```

**ACK 示例：**

```json
{"type":"ack","cmd":"enable_auto_record","result":0,"ts":1787808964108302}
```

> 详细字段表见上表 §2.1；App 查询字段见 §4.3；命令表见 [三方对表](./三方对表-命令与上报.md)（在线 `/#docs-cmd`）。

### 2.2 运行态 `state` / `event` 建议枚举

完整定义见 **[三方对表 §2.2](./三方对表-命令与上报.md#22-event--state-枚举运行态)**。

#### `state`（当前运行态 → `last_state` / `state_label` / `in_sleep`）

| `state` | 含义 | App `state_label` | App `in_sleep` |
|---------|------|-------------------|----------------|
| `idle` | 空闲 | 空闲 | false |
| `recording` | 录音中 | 录音中 | false |
| `playing` | 播放 TTS/叫声 | 播放中 | false |
| `locating` | 定位中 | 定位中 | false |
| `ota` | OTA 升级中 | 升级中 | false |
| `sleep` / `sleeping` | 夜间休眠 | **睡眠** | **true** |
| `night_sleep` / `deep_sleep` | 深度/夜间休眠 | **睡眠** | **true** |

设备进入睡眠后应立刻发 `type=status`，至少带 `state:"sleep"`（推荐同时带 `event:"sleep_enter"`）。网关写入 `last_state`，状态接口返回 `last_state`、`state_label="睡眠"`、`in_sleep=true`。

#### 夜间休眠如何进入（固件侧）

1. 云端下发 **`enable_sleep`=`"1"`**（设备上报 `sleep_enabled:1`）。
2. 云端下发 **`set_sleep_window`**，格式 **`"开始小时:结束小时"`**（24h），如 `"8:10"` 表示每天 8 点～10 点（设备样例），`"0:6"` 表示 0 点～6 点。
3. **仅在整点**判断一次：当前本地小时是否落在窗口内；在窗口内则进入睡眠，上报 `state:"sleep"`；离开窗口或 `enable_sleep=0` 后上报 `state:"idle"`（可用 `event:"sleep_exit"`）。
4. 未开 `enable_sleep`、或窗口未配置时，不要进睡眠。

与功耗档位 `tier`（normal/light/deep）正交：`tier` 是静音时长推出来的浅睡/深睡；`state=sleep` 是夜间休眠窗口。任一满足时 App 的 `in_sleep` 均为 true。

```json
{"type":"status","event":"sleep_enter","state":"sleep","sleep_enabled":1,"sleep_window":"8:10","tier":"normal","bat":46,"ts":1790038804965931}
```

状态接口对应该看到：

```json
{
  "last_state": "sleep",
  "state_label": "睡眠",
  "last_event": "sleep_enter",
  "in_sleep": true,
  "sleep_enabled": true,
  "sleep_window": "8:10"
}
```

#### `event`（瞬时事件 → `last_event`，与 `state` 成对带）

| `event` | 建议 `state` |
|---------|--------------|
| `audio_start` | `recording` |
| `audio_end` | `idle` |
| `play_start` | `playing` |
| `play_end` | `idle` |
| `sleep_enter` | `sleep` |
| `sleep_exit` | `idle` |
| `locate` / `locate_update` | `locating` |

录音开始/结束务必立刻发 `type=status`，不要等 25s 心跳。

### 2.3 运动姿态 `motion`（走 / 跑 / 站 / 趴 / 躺）

姿态枚举以本节为在线文档准绳（嵌入式文档、三方对表只保留同一张表的摘要）。

| `motion` | 中文 | App `motion_label` |
|----------|------|--------------------|
| `walk` | 走 | 走 |
| `run` | 跑 | 跑 |
| `stand` | 站 | 站 |
| `prone` | 趴 | 趴 |
| `lie` | 躺 | 躺 |

也可直接发中文 `走`/`跑`/`站`/`站立`/`趴`/`躺`，网关规范成上表英文。

姿态变化立刻发 `type=status`（可带 `event=motion_change`）；**25s `type=ping` 也建议顺带当前 `motion` + 最近数点 `imu`**。音频元数据里的 `motion` 写入该分片，并刷新状态快照。

```json
{"type":"status","event":"motion_change","motion":"stand","bat":74,"ts":1756210523456789}
```

### 2.4 功耗档位 `tier`（正常 / 浅睡 / 深睡）

与运行态 `state`、运动姿态 `motion` **正交**；档位变化立刻发 `type=status`，25s `ping` 也建议顺带当前档位。

| `tier` | 含义 | App `tier_label` | `in_sleep` |
|--------|------|------------------|------------|
| `normal` | 正常工作态 | 正常 | false（除非 state/event 另为 sleep 类） |
| `light` | 浅睡：静音 ≥5min 触发；有网保 WiFi / 无网关射频保 BLE | 浅睡 | **true** |
| `deep` | 深睡：浅睡后再静音约 5min；充电/配网态阻断 | 深睡 | **true** |

```json
{"type":"status","event":"tier_change","tier":"light","bat":74,"ts":1756210523456789}
{"type":"ping","tier":"normal","bat":74,"ts":1756210523456789,...}
```

### 2.5 完整示例：心跳 + 配置（推荐）

```json
{
  "type": "ping",
  "bat": 74,
  "charge": true,
  "rssi": -66,
  "fw": "2.0.0",
  "proto_ver": 1,
  "pid": "623",
  "breed": "cat",
  "db": -600,
  "ts": 1787808964108302,
  "volume": 65,
  "sensitivity": 80,
  "auto_record": 1,
  "translate_enabled": 1,
  "sleep_enabled": 1,
  "sleep_window": "0:6",
  "loc_interval_ms": 30000,
  "motion": "walk",
  "tier": "normal",
  "imu": [
    {"ts": 1787808964108302, "acc": [0.01, 0.0, 1.0], "gyro": [0.5, -0.2, 0.1]}
  ]
}
```

网关回：`{"type":"pong"}`

> 心跳里的 `imu` 带**最近 1～数点**即可；录音对齐仍靠音频帧完整 `imu`。

### 2.5 完整示例：录音结束立刻发 status

```json
{
  "type": "status",
  "bat": 74,
  "charge": true,
  "rssi": -68,
  "fw": "2.0.0",
  "pid": "623",
  "breed": "cat",
  "event": "idle",
  "state": "idle",
  "motion": "lie",
  "imu": [
    {"ts": 1787808964108302, "acc": [0.02, -0.01, 0.99], "gyro": [0.1, 0.0, -0.05]}
  ],
  "ts": 1787808964108302,
  "volume": 65,
  "sensitivity": 80
}
```

> ⚠️ **不要**等下一轮 25s 心跳才从 `recording` 变 `idle`，否则 App 卡片会长时间显示「录音中」。

### 2.6 关于 `bound`（设备 vs App）

- 设备 JSON 里的 `bound` **可继续上报**（兼容旧固件）
- **App 状态接口的 `bound` 由网关计算**：`pid` 与 `breed` 均有效非空 → `bound=1`，否则 `0`
- 固件侧：`pid` 未绑定填 `""`，`breed` 用 `"dog"`/`"cat"` 等字符串，**不要用** `0`/`1` 占位品种

## 3. 下行命令与配置影子（固件需执行的 cmd）

App / 测试台通过 `POST /api/v1/device/cmd` 下发；设备收到后应 **执行并尽量在下一轮 ping/status 里回显真值**。

| cmd | data 示例 | 设备动作 | 网关影子字段 |
|-----|-----------|----------|--------------|
| `set_volume` | `"65"` | 设置音量 | `volume` |
| `set_sensitivity` | `"80"` | 设置灵敏度 | `sensitivity` |
| `enable_translate` | `"1"` / `"0"` | 开关自动录音（旧名）；执行后回 `type=ack` | 成功 ACK 后写 `auto_record` + `translate_enabled` |
| `enable_auto_record` | `"true"` / `"false"` | 开关自动录音（推荐）；亦兼容 `1`/`0` | 成功 ACK 后写 `auto_record` + `translate_enabled` |
| `enable_sleep` | `"1"` / `"0"` | 开关夜间休眠 | `sleep_enabled` |
| `set_sleep_window` | `"0:6"` | 休眠时段 | `sleep_window` |
| `set_loc_interval` | `30000` 或 `"30000"` | 定位间隔 ms | `loc_interval_ms` |
| `set_bitrate` | `"0"` / `"1"` / `"2"` | 设置**实时翻译**音频上行码率（见下） | —（暂无影子；不影响 status 快照） |
| `set_record_mode` | `"0"` / `"1"` | 录音模式；0：连续模式；1：事件模式；执行后回 `type=ack`；非法值 `result=1` | — |
| `record_now` | `{}` | 约 3s 手动录音一次 | — |
| `enter_calib_ble` | `{}` | 进入 BLE 标定；`ack.result=0` 后**主动离线**（`offline_reason=calib_ble`）；App 先订 FFE5 再写 FFE4=`0x0D` | — |

**码率（`set_bitrate`）范围（设计定稿）：**

| data | 码率 | 作用范围 |
|------|------|----------|
| `"0"` | 16kbps | **只影响**实时翻译音频上行：`type=audio` 的 OPUS Binary 帧 |
| `"1"` | 24kbps（默认） | 同上 |
| `"2"` | 32kbps | 同上 |

- **不影响** `record_now`：约 3s 手动录音走**固定 32kbps 独立编码器**（回放音质优先，设计如此）。
- 完整命令表见 [三方对表 §1](./三方对表-命令与上报.md)（在线 `/#docs-cmd`）。

离线时命令进 Redis 队列，上线后自动下发。一般配置影子在**入队/下发时**即写入；**例外：`enable_auto_record` / `enable_translate` 须等设备成功 ACK 才改 `auto_record` 状态**（见 §2.1.1）。

## 4. App 查询：`/api/v1/device/status` 响应字段

成功：`{"code":1,"data":{...}}`（管理端与 App 路径字段一致）

### 4.1 连接与在线（服务端，无需设备额外字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| `online` | bool | 是否在线（WS + Redis） |
| `conn_id` | string | 当前连接 ID |
| `connected_at` | int64 | 本次连接建立时间（ms） |
| `last_seen_at` | int64 | 最近上行/Ping 时间（ms） |
| `last_report_at` | int64 | 最近业务上报时间（ms） |
| `seconds_since_seen` | int64 | 距 `last_seen_at` 秒数（服务端计算） |
| `offline_reason` | string | 离线原因；空=普通掉线/未知；**`calib_ble`**=`enter_calib_ble` 成功后的**主动离线**（BLE 标定中） |
| `active_offline` | bool | 是否为主动离线（当前仅 `offline_reason=calib_ble`）；App 宜展示「标定中」而非「掉线」 |
| `offline_cmd_pending` | int64 | 离线指令队列长度 |

### 4.2 设备快照（来自上行）

| 字段 | 说明 |
|------|------|
| `b` | 电量 0~100（上行字段名 `bat`） |
| `charge` | bool，是否充电 |
| `rssi` | WiFi dBm |
| `fw_ver` | 固件版本（上行字段名 `fw`） |
| `proto_ver` | 协议版本 |
| `ch` | WiFi 信道 |
| `db` | 声压 dBFS |
| `pid` / `breed` | 档案与品种 |
| `bound` | **网关计算**（见 §2.6） |
| `last_state` / `state_label` / `last_event` | 最近运行态英文 / 中文（空闲、睡眠…） / 最近事件 |
| `motion` / `motion_label` | 运动姿态英文 / 中文（走/跑/站/趴/躺）；来自 ping/status/音频 |
| `tier` / `tier_label` | 功耗档位：`normal`/`light`/`deep` → 正常/浅睡/深睡 |
| `imu` | 最近一次上报的 IMU 数组（ping/status/音频均可刷新）；未上报为 `null` |
| `in_sleep` | 由 `last_state`/`last_event` 为 sleep 类 **或** `tier` 为 `light`/`deep` 推导 |
| `last_loc_*` / `loc_type` / `loc_speed` | 最近定位 |

### 4.3 配置（设备真值或下行影子；键始终存在）

| 字段 | 类型 | 说明 |
|------|------|------|
| `volume` | int\|null | 0~100；未设置时为 `null` |
| `sensitivity` | int\|null | 0~100 |
| **`auto_record`** | bool | **自动录音开关**（推荐）；**默认 `false`**；成功 ACK / 设备上报后更新；控制设备是否自动上录音文件（网关按 `kind` 分桶处理，见 `upload_audio.txt`） |
| `translate_enabled` | bool | 与 `auto_record` 同义（兼容旧 App）；默认同步为 `false` |
| `sleep_enabled` | bool\|null | 夜间休眠开关 |
| `sleep_window` | string | 如 `"0:6"`；未设置时为 `""` |
| `loc_interval_ms` | int\|null | 定位间隔毫秒 |
| `config_source` | string | `device` / `shadow` / 空 |
| `config_updated_at` | int64 | 配置最后更新时间（ms） |

## 5. 固件联调 Checklist

- [ ] 25s 发 `type=ping`，带 `bat/charge/rssi/fw/pid/breed/db/ts`
- [ ] 同上心跳带 `volume/sensitivity/auto_record`（或旧字段 `translate_enabled`）/`sleep_enabled/sleep_window`（至少一项）
- [ ] `enable_auto_record` 成功 ACK 后状态接口更新；事件流（`kind=0`）正常入库翻译；录音文件（`kind=1`）按 `audio.*` 分桶入库/归档，不与事件流混拼
- [ ] 同上心跳建议带当前 `tier`（`normal`/`light`/`deep`）
- [ ] 录音开始/结束各发一条 `type=status`，`state`=`recording`/`idle`
- [ ] **夜间休眠**：`enable_sleep=1` + `sleep_window`；整点进窗后上报 `state=sleep`；状态接口应见 `last_state=sleep`、`state_label=睡眠`、`in_sleep=true`
- [ ] 档位变化立刻发 `type=status` + `tier`（可带 `event=tier_change`）
- [ ] 收到 `set_volume` 等 cmd 后本地生效，并在 **下一条 ping/status** 回显新值
- [ ] 关键 cmd 回 `type=ack`，`result=0`（已确认：`enable_auto_record` / `enable_translate`、`set_record_mode`、`enter_calib_ble`；非法 `set_record_mode` 回 `result=1`）
- [ ] 用 curl 查状态确认字段已刷新：

```bash
curl -s 'https://api.example.com/api/v1/device/status?sn=PT-xxx' | jq .data
```
