# 设备音频翻译流水线

设备 WS 上报音频分片 → `audio_chunk` 入库 → **`end=true` 时异步**：

1. 用连接上的 **SN** 查 **`a_emb_sn`**
2. **事件流原帧 zip**（与 stitch/转码并行）：本段 `audio_chunk` 真实 Opus 打成 zip 上传 → `origin_raw_url`（无 PLC、不多段拼接）
3. **ffmpeg** 将设备裸 Opus 转为 **MP3**（或 `wav`）上传 OSS → `origin_audio_url`（App 可播；可含补洞/多段 stitch）
4. 若 `translate.enabled` 且 OSS/AI/百度齐全，继续 AI → 百度 TTS → **App 用 MP3 上传 OSS**（`audio_url`），**设备仍下发裸 Opus 帧**，并写入 `a_emb_translate.device_opus`（可 `POST …/tts/replay` 再次下发）
5. 回写 `status=ok|fail`

**绑定门禁**：`a_emb_sn.bind_user_id` 为 0/空，或 `bind_pet_id` 为 0/空（或无该 SN 记录）时，网关**不接收**该设备上行录音（不入库/不投递 Kafka）；流水线端同样跳过会话。绑定结果连接内缓存约 30s。

**链路约定**：设备 ↔ 网关 = 裸 Opus；App 消费 OSS URL = MP3/WAV。

**双通路按 `kind` 分桶（可配置）**：设备同一次叫声可能上两路音频（见 `docs/upload_audio.txt`）：

| 通路 | 判据 | 默认行为（`audio.accept=both`） |
|------|------|--------------------------------|
| 事件流 | `kind=0`（无 kind 默认 0） | **入库 + 翻译**（`translate=event`） |
| 录音文件 | `kind=1` | **入库 + OSS 归档**（`archive_other=true`，不翻译） |

两路按各自 `seq=0`…`end=1` 分段，补发并回原段，**绝不混拼**。`auto_record` 只影响设备是否自动产生录音文件。

`translate.enabled=false` 时仍会转码上传原音并落 `a_emb_translate`（需 `oss.enabled=true`）。

## 配置

```yaml
database:
  enabled: true          # 必开：才能写 a_emb_sn 查询 + a_emb_translate
  driver: mysql

translate:
  enabled: true
  push_to_device: true
  ffmpeg_path: "ffmpeg"
  opus_bitrate: 24000
  app_audio_format: mp3
  app_mp3_bitrate: 64000
  app_sample_rate: 16000

audio:
  accept: both           # event | file | both
  translate: event       # event | file | both | none
  archive_other: true    # 未翻译通路 end 时仍 OSS 归档

oss:
  enabled: true
  # ...

baidu:
  enabled: true
  aue: 4
  # ...

ai:
  enabled: true
  base_url: "http://host:port"
```

完整翻译依赖：`database` + `translate.enabled` + `oss` + `ai` + `baidu` + 系统 `ffmpeg`（含 libmp3lame、libopus）。  
仅原音落库：需 `database.enabled=true` + `oss.enabled=true` + `ffmpeg`。

## App vs 设备

| 消费方 | 格式 | 获取方式 |
|--------|------|----------|
| App | **MP3**（`audio/mpeg`，可配 `wav`） | `origin_audio_url` / `audio_url` OSS 公网地址 |
| ESP32 | 裸 OPUS 包，每条 WS Binary 一帧 **20ms**（上行）；下行 TTS 为 60ms | 网关在线时自动 `SendTTSFrames` |
设备离线时推送失败只打警告，翻译记录仍为 `ok`（App 仍可播 OSS）。

## App 查询

```bash
curl -k "https://127.0.0.1:8443/api/app/v1/translates?sn=TEST_SN_001"
```

| 字段 | 说明 |
|------|------|
| user_id / emb_id | 来自 `a_emb_sn.bind_user_id` / `a_emb_sn.id` |
| emb_sn | 设备 SN |
| origin_audio_url | 设备原音频可播文件 OSS（转码后） |
| origin_raw_url / origin_raw_frames | 事件流原帧 zip OSS（裸包，无 PLC）；与可播文件并列 |
| audio_url | TTS 人声 OSS（App 播放） |
| device_opus / device_opus_frames | 设备下行裸 Opus（长度前缀打包）；列表字段 `has_device_opus` |
| translate_text / result_says | AI `pet_says`（无有效声纹时 result_says 有默认文案） |
| origin_audio_duration | 原音频时长（秒，约估） |
| audio_kind / audio_kind_label | `0`/`event` 事件流；`1`/`file` 录音文件 |
| pid | 设备上报；空则用 `a_emb_sn.bind_pet_id` |
| status | `pending` / `ok` / `fail` |
| createtime | 创建 Unix 秒 |
| resulttime | 完成 Unix 秒 |

## 日志关键字

- `原音频已转码并上传OSS（App 可播）`
- `TTS已上传OSS（App 可播）`- `TTS已推送设备` / `TTS推送设备失败`
- `翻译流水线完成` / `翻译流水线失败`
- `ffmpeg 转 opus 失败` → 检查 PATH / libopus
