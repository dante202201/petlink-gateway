# App ↔ 设备 BLE 通道协议

> 面向对象：**App / 固件 BLE 联调**  
> 范围：手机与设备之间的 BLE 控制 / Notify / 大数据文本通道  
> **不在网关实现**：PetLinkGateway 只处理 HTTPS / WSS；BLE 由 **App 与固件** 完成。  
> 云端设备协议见 [嵌入式接口使用文档](./嵌入式接口使用文档.md)；WS 命令对表见 [三方对表-命令与上报](./三方对表-命令与上报.md)。

---

## 1. BLE 命令字表（App → 设备）

近场控制走 **二进制命令码**（不是 WSS 的 `{"type":"cmd",...}` JSON）。下表为当前已给出的控制码；与云端同名能力应对齐语义，通道互不替代。

| 码 | 名称 | 载荷 | 说明 | 对应 WSS `cmd`（若有） |
|----|------|------|------|------------------------|
| `0x01` | 开始配网 | `[0x01]` | 进入配网；**超时 30 秒**（SRS 定稿；勿按旧文档 60 秒） | —（仅 BLE） |
| `0x02` | 恢复出厂 | `[0x02]` | 恢复出厂设置 | `factory_reset` |
| `0x03` | 断开 WiFi | `[0x03]` | 断开当前 WiFi | —（仅 BLE） |
| `0x04` | 查状态 | `[0x04]` | 查询设备状态 | —（仅 BLE；回包格式待固件补） |
| `0x05` | 查绑定 | `[0x05]` | 查询绑定状态 | —（仅 BLE；回包格式待固件补） |
| `0x06` | 设灵敏度 | `[0x06, 值]` | `值` = **0～100** | `set_sensitivity`（WS `data` 为字符串如 `"80"`） |
| `0x07` | 绑定设备 | `[0x07]` | 绑定 | `bind_device`（WS 另带 `{pid,breed}`；BLE 是否跟参 **待补**） |
| `0x08` | 解绑 | `[0x08]` | 解绑 | `unbind_device` |
| `0x09` | 产测 | `[0x09, 动作]` | `0`=确认 `1`=拒绝 `2`=中止 | —（仅 BLE / 产线） |
| `0x65`～`0x6D` / `0xC9`～`0xCF` | 播放固定叫声 | 与本地 cry 文件映射一致 | 猫/狗情绪叫声 | `play_cry`，WS：`data:"0x65"` 等；见 [固定叫声对照表](./固定叫声play_cry对照表.md) |
| `0x00` | 未匹配情绪 | — | 兜底 | `play_cry`，`data:"0x00"` |
| **`0x0D`** | **进入标定** | **`[0x0D]`** 写到 **FFE4** | 麦克风/传感器 BLE 标定；须先订 **FFE5** 再写 | `enter_calib_ble`（WSS 先 ack 后设备离线） |

**说明**

- 载荷列为逻辑字节序示意；特征 UUID / Write / Notify 帧头以固件为准。  
- `0x01`～`0x09` 为近场/产测常用；`0x65` 与 WSS `play_cry` 已对齐。  
- 其余 WSS 命令（时区、睡眠窗、OTA 等）**尚无 BLE 码**时，只走云端 WSS，或等固件续表。  
- **网关不解析这些命令码。**

### 1.1 WiFi 配网超时

| 项 | 约定 |
|----|------|
| 超时 | **30 秒**（固件按 SRS） |
| App | 配网 UI / 文档若仍写 60 秒请改成 30，避免用户空等 |

## 1.2 设备本地录音文件格式（原 MP3 → OPUS）

设备落盘 / 经 BLE 传出的录音文件（**不是** WSS 实时 Text+Binary 分片）：

| 项 | 约定 |
|----|------|
| 编码 | **OPUS**（已不再使用 MP3） |
| 后缀 | **`.opus`** |
| 容器 | 连续帧：每帧 = **`uint16` 小端长度** + **该长度的裸 OPUS 包** |
| 体量 | 约 **3 秒 ≈ 9KB** |
| 条数 | 设备侧最多保留 **3 条** |

```text
[len0:u16-le][opus_packet_0][len1:u16-le][opus_packet_1]...
```

App / 云端若拉取这类文件：按小端长度切开再解码；**不要**当 MP3，也**不要**当 Ogg 封装。  
WSS 上报仍是「每帧 Binary = 一个裸 OPUS 包」（无文件级长度前缀），网关入库逻辑不变。

## 2. STAT Notify：充电状态

充电走 **BLE STAT 特征 Notify 文本**（无空格）：

```text
CHARGE:<电量%>
```

| 项 | 约定 |
|----|------|
| 示例 | `CHARGE:78` |
| 电量 | 整数 `0`–`100` |
| 可选 | 尾部 `%` 也可认（`CHARGE:78%`），推荐不带 |
| 语义 | 正在充电并上报当前电量 |

上云若另有 JSON `notify`，见嵌入式文档；**本通道与云端互不替代**。

## 3. 大数据分包（Base64 / 可选 AES）

适用于经 BLE 文本特征下发或上报、需先处理原始二进制再 Base64 切包的场景。

### 2.1 字段含义

| 字段 | 含义 |
|------|------|
| `l` | **原始数据字节数**（Base64 / AES 加密**之前**），不是 `d` 的长度，也不是整包 JSON 长度 |
| `d` | 本包 Base64 **正文片段**（字符） |
| `s` | 当前包序号，从 `0` 递增 |
| `t` | 总包数；单包直发时 `t=1` |
| `c` | 帧校验/会话相关字段（与固件约定一致）；**`l`/`c`/`t` 全帧共用、每包都带** |

两个限制分开算：

| 限制 | 口径 |
|------|------|
| **`d` 每包上限** | 固定 **≤ 200 字符**（协商 MTU 247 时的正文上限），与 `t` 无关 |
| **单包直发 `t=1`** | 看原始长度 **`l`**，不是看 `d`、也不是看整包 JSON |

### 2.2 实现判据（App / 固件）

1. 组装整包 JSON（`d` 的 Base64 片段 + 键名等）。
2. **整包 ≤ 当前协商 MTU 可用空间** → 单包 `t=1` 直发。
3. **超了** → `t≥2` 分包：每包 `d ≤ 200` 字符；`l`/`c`/`t` 全帧共用、每包都带；`s` 从 `0` 递增。

### 2.3 MTU 与键名余量

整包 JSON 的**键名等开销（约 43 字节）不计入 `d` 的 200**，占用 ATT 净荷余量：

| 协商 MTU | ATT 净荷约 | 能否装下 `200(d)+43(键名)` | 单包经验值 |
|----------|------------|---------------------------|------------|
| **247** | 244 | `200+43=243`，一包放得下 | 明文 **`l ≤ 150`** |
| **185** | 182 | 放不下满额 `d=200`+键名 | 单包约 **`l ≤ 100`**；超了 `t≥2` |

经验速记：**MTU 247 → 单包 `l≤150`；MTU 185 → 单包 `l≤100` 左右。**

### 2.4 Base64 与明文单包阈值

```text
b64_len = 4 × ⌈raw_len / 3⌉
```

- `l=150` → Base64 正好 **200** 字符 → 恰好卡在 `d` 上限 → 明文单包口径用 **`l ≤ 150`**。
- `l=360` → Base64 **480** 字符 → `⌈480/200⌉=3` → **`t=3`**（不是 2）。

```json
{"s":0,"t":3,"l":360,"c":"...","d":"<最多200字符>"}
{"s":1,"t":3,"l":360,"c":"...","d":"<最多200字符>"}
{"s":2,"t":3,"l":360,"c":"...","d":"<剩余>"}
```

| 原始 `l` | Base64 字符 | 明文能否 `t=1`（MTU 247） |
|----------|-------------|---------------------------|
| ≤150 | ≤200 | 可以 |
| 151 | 204 | 须 `t≥2` |
| 360 | 480 | **`t=3`** |
| 400 | ≈536 | `t≥3`（勿用「原始 ≤400 可单包」） |

### 2.5 正式 AES-CBC 后

PKCS7 补齐到 16 字节倍数后再 Base64：

- `l=145`～`160` 会被补成 **160** → Base64 **216** 字符 **> 200**。
- 加密版单包阈值改为 **`l ≤ 144`**（144→补齐仍 144→Base64 192 ≤ 200）。

联调阶段若关闭加密，仍按明文 **`l ≤ 150`（MTU 247）** / **`l ≤ 100` 左右（MTU 185）**。

## 4. BLE 标定（`enter_calib_ble` / FFE4=`0x0D`）

云端先下发 WSS 命令让设备进入标定态并离线，随后 **App 近场 BLE** 完成标定。标定命令在 BLE 侧只有一条：往 **FFE4** 写单字节 **`0x0D`**。

### 4.1 云端 WSS（网关透传）

```json
{"type":"cmd","cmd":"enter_calib_ble","data":{}}
```

设备回执：

```json
{"sn":"...","type":"ack","cmd":"enter_calib_ble","result":0,"ts":...}
```

| 项 | 约定 |
|----|------|
| `result=0` | 已进入标定模式 |
| 随后 | 设备会 **断开 WSS/离线**，App 切到 BLE 交互 |
| 状态标记 | 网关记 **`offline_reason=calib_ble`**、`active_offline=true`、`last_event=calib_ble_enter`（与普通掉线区分；见 [设备状态与配置上报 §4.1](./设备状态与配置上报.md)） |
| 下发入口 | `POST /api/v1/device/cmd` 或 App 等价路径，`cmd=enter_calib_ble`，`data={}` |

### 4.2 App BLE 时序（务必按顺序）

1. **先订阅 Notify 特征 `FFE5`**（不订就收不到回执）。
2. 往写特征 **`FFE4` 写 1 字节 `0x0D`**（标定命令仅此一条）。
3. `FFE5` 先回文本：`CALIB:START`。
4. 约 **8 秒** 后再回：
   - 成功：`CALIB:OK`
   - 失败：`CALIB:FAIL` + 原因（如 `CALIB:FAIL busy`；具体后缀以固件为准）

```text
App                          设备
 |-- Subscribe FFE5 -------->|
 |-- Write FFE4: 0x0D ------>|
 |<-- Notify FFE5 CALIB:START|
 |        (~8s)              |
 |<-- Notify FFE5 CALIB:OK   |
 |    或 CALIB:FAIL <原因>   |
```

### 4.3 注意

- **订购 FFE5 必须在写 FFE4 之前**，否则 `CALIB:*` 回执会丢。
- 标定期间设备离线属**主动离线**（预期）；App 查 `/device/status` 时看 `active_offline` / `offline_reason=calib_ble`，勿当普通掉线告警。完成后回 Wi‑Fi/WSS，重连后标记清除。
- 网关**不解析** `CALIB:*` 文本，只透传 `enter_calib_ble` 与 `ack`，并写入上述状态标记。

## 5. 与网关的边界

| 职责 | 谁做 |
|------|------|
| BLE MTU 协商、JSON 组包/拆包、`d≤200`、`t=1` 判据、AES、**标定 FFE4/FFE5** | **App + 固件** |
| HTTPS / WSS、`enter_calib_ble` 透传与 ack 日志、云端音频分片 | **PetLinkGateway** |

网关**不**根据 BLE `s/t/l/d` 做分包或合包，也**不**解析 `CALIB:*`。
