# 固定叫声 `play_cry` 对照表（服务端下发）

> **用途**：服务端 / App / 运营通过网关下发 `play_cry`，设备按 **指令 ID（Hex）** 播放本地预置叫声文件。  
> **通道**：WSS `{"type":"cmd","cmd":"play_cry","data":"<Hex>"}`；BLE 同 Hex 命令字。  
> **范围**：猫 9 类 + 狗 7 类，共 16 种；未匹配用 `0x00`。  
> **在线查阅**：测试台协议文档 → **固定叫声**（`/#docs-play-cry`）  
> **更新**：2026-08-27

---

## 1. 下发格式

**HTTP（管理 / App 业务侧调网关）：**

```http
POST /api/v1/device/cmd
Content-Type: application/json

{"sn":"PT-xxx","cmd":"play_cry","data":"0xCB"}
```

**设备收到的 WSS 帧：**

```json
{"type":"cmd","cmd":"play_cry","data":"0xCB"}
```

| 字段 | 说明 |
|------|------|
| `cmd` | 固定 `play_cry`（也可用请求体里的 `type` 字段作命令名） |
| `data` | **字符串** Hex，如 `"0x65"`、`"0xCB"`（**不是** `{}`） |
| 设备动作 | 查本地叫声库，播放对应 `.opus`；播完可回 `ack` |

> `data` 必须是字符串。例如狗「饥饿」→ `"0xCB"`。

## 6. 固件要点

- 叫声文件预置在设备本地（或 OTA 资源包），**网关不下发音频内容**，只下 Hex 指令。
- 收到 `play_cry` 后：查表 → 播对应 Opus → 建议回 `{"type":"ack","cmd":"play_cry","result":0}`。
- 播放期间 `type=status` 建议 `state=playing`，结束回 `idle`。
- 与 BLE：`0x65`～`0x6D`（猫）、`0xC9`～`0xCF`（狗）与 WSS `data` 字符串一致。
